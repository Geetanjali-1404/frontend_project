1. PROJECT OVERVIEW & MISSION
================================================================================
GoBeyond Travels is a full-stack cultural travel platform designed specifically 
for authentic, off-beat Indian heritage tourism. Unlike conventional mass-tourism 
platforms that funnel visitors into crowded tourist traps, GoBeyond Travels 
connects travelers directly with indigenous historians, certified native custodians, 
and ancestral artisan guilds.

Core Platform Pillars:
- Anti-Over-Tourism: Real-time crowd density tracking indicators so conscious 
  travelers can choose tranquil, sustainable visit windows.
- Economic Fair Wage Charter: 85% of all booking revenue flows directly to local 
  guides and artisan custodians, with zero-middleman commissions.
- Cultural Depth: Focus on living oral histories, Dhokra lost-wax casting, 
  1,000-year-old mud monasteries, Mask-making sattras, and teak mansions.
- AI Concierge: Built-in AI travel guide assistant to curate custom itineraries 
  and explain regional customs, road connections, and cultural etiquette.

2. SYSTEM ARCHITECTURE & TECH STACK
================================================================================
The project is built with a separated client-server decoupled architecture:

FRONTEND:
- Markup: Semantic HTML5 with responsive mobile-first layouts
- Styling: Custom CSS3 with CSS Custom Properties (Variables), Flexbox, CSS Grid,
  and smooth micro-animations (no heavy external CSS framework required)
- Typography: Cinzel (traditional headers), Plus Jakarta Sans & Outfit (body)
- Icons: Crisp vector Lucide-style SVG icon system and FontAwesome 6
- Data Visualizations: Chart.js for booking breakdown and status visuals
- Real-Time Communication: Socket.io Client for live crowd meter updates
- Scripting: Modular ES6+ JavaScript with unified API client and fallback cache

BACKEND:
- Runtime: Node.js (v18+)
- Framework: Express.js (REST API Server)
- Database ORM: Prisma ORM
- Database: PostgreSQL (hosted on Render / Supabase)
- Real-Time Layer: Socket.io for bi-directional crowd density and notifications
- Authentication: JSON Web Tokens (JWT) with bcryptjs password hashing and RBAC 
  (Roles: TRAVELER, GUIDE, ADMIN)
- File Uploads: Multer for guide government ID and avatar verification documents
- AI Integration: API endpoints for custom itinerary generation and review summaries

The frontend is structured as a multi-page web application with unified state 
management, modal controls, and API abstraction:

  Global layout manager: handles modals (Guide profile, Route details, Booking checkout),
  toast alerts, top navigation active indicators, and user session sync.
- assets/js/data.js:
  Local mock data and fallback datasets ensuring the frontend renders smoothly 
  even when offline or when backend instances are waking from cold start.
- assets/js/home.js: Hero search and homepage destination card renderer.
- assets/js/destinations.js: Destination catalog search, filters, and crowd meter.
- assets/js/packages.js: Expedition package rendering and checkout triggers.
- assets/js/reviews.js: Review listing, ratings aggregation, and review submission.
- assets/js/auth.js: Form validation and authentication token handling.
- assets/js/guide-onboarding.js: Guide application form handler with file uploads.

4. BACKEND ARCHITECTURE & REST API SPECIFICATION
================================================================================
The Express backend is organized into a clean MVC structure:

DIRECTORY LAYOUT:
backend/
├── prisma/
│   ├── schema.prisma            # PostgreSQL relational schema
│   └── seed.js                  # Database seeder with authentic Indian destinations
├── src/
│   ├── config/                  # App configuration & DB connection
│   ├── controllers/             # Request handlers
│   │   ├── adminController.js
│   │   ├── aiController.js
│   │   ├── authController.js
│   │   ├── bookingController.js
│   │   ├── crowdController.js
│   │   ├── destinationController.js
│   │   ├── guideController.js
│   │   ├── notificationController.js
│   │   ├── paymentController.js
│   │   ├── recommendationController.js
│   │   ├── reviewController.js
│   │   └── routeController.js
│   ├── middleware/              # Auth, validation, uploads, error handling
│   ├── routes/                  # Express route definitions (src/routes/api.js)
│   ├── services/                # Socket.io, AI service, Trust score calculation
│   └── server.js                # Server entry point & Socket.io server

CORE REST API ENDPOINTS:
- System:
  * GET  /api/health             - System status, timestamp, platform modules

- Authentication & Users:
  * POST /api/auth/register      - Create new traveler or guide account
  * POST /api/auth/login         - Authenticate user & return JWT token
  * GET  /api/auth/me            - Retrieve current authenticated profile

- Destinations:
  * GET  /api/destinations       - List all heritage destinations (supports filters)
  * GET  /api/destinations/:id   - Detailed destination view with guides & reviews

- Guides & Guilds:
  * GET  /api/guides             - List certified local guides
  * GET  /api/guides/:id         - Specific guide bio, badges & verified tours
  * POST /api/guides/apply       - Guide onboarding application (multipart)
  * PATCH /api/guides/:id/status - Admin status update (APPROVED, REJECTED, TIER)

- Bookings:
  * GET  /api/bookings           - Retrieve user bookings
  * POST /api/bookings           - Create new booking
  * GET  /api/bookings/:id       - Booking status & guide details
  * POST /api/bookings/:id/cancel- Cancel booking with refund processing
  * GET  /api/bookings/availability - Real-time slot availability check

- Crowd Density Engine:
  * GET  /api/crowd              - Global crowd levels across all destinations
  * GET  /api/crowd/:destId      - Specific site crowd percentage & trend
  * POST /api/crowd/report       - Guide crowd reporting endpoint

- AI Engine:
  * POST /api/ai/chat            - Interactive conversational heritage assistant
  * POST /api/ai/itinerary       - Custom personalized itinerary generator
  * GET  /api/ai/summarize/:id   - AI review summary for a destination

- Administration:
  * GET  /api/admin/metrics      - Platform KPIs (users, gross volume, guide share)
  * GET  /api/admin/guides/pending - Queue of awaiting guide applications
  * PATCH /api/admin/users/:id/block - User access moderation

5. DATABASE SCHEMA & DATA MODELS (PRISMA)
================================================================================
Defined in `backend/prisma/schema.prisma`:

- User:
  id, email, passwordHash, name, role (TRAVELER, GUIDE, ADMIN), phone, avatar,
  createdAt, updatedAt.
- GuideProfile:
  id, userId (FK -> User), bio, city, state, experienceYears, governmentIdUrl,
  badgeTier (NOVICE, CERTIFIED_CUSTODIAN, MASTER_HISTORIAN), verificationStatus,
  dailyRate, languages, trustScore, totalToursCompleted.
- Destination:
  id, slug, name, tagline, description, city, state, region, category,
  crowdPercent, crowdLevel (peaceful, moderate, high), heroImage, culturalTags,
  historicalEra, latitude, longitude, bestVisitingMonths.
- Booking:
  id, bookingRef, userId (FK -> User), destinationId (FK -> Destination),
  guideId (FK -> GuideProfile), startDate, endDate, groupSize, totalAmount,
  status (PENDING, CONFIRMED, COMPLETED, CANCELLED), paymentStatus.
- Review:
  id, userId (FK -> User), destinationId (FK -> Destination), guideId,
  rating (1-5), comment, trustScoreWeight, guideReply, createdAt.
- Notification:
  id, userId (FK -> User), title, message, type, read, createdAt.

8. LOCAL DEVELOPMENT & SETUP GUIDE
================================================================================

To run the full stack locally on your computer:

A. Clone the Repository:
   git clone https://github.com/Geetanjali-1404/frontend_project.git
   cd frontend_project

B. Run Backend:
   cd backend
   npm install
   npx prisma generate
   # Ensure .env exists with PORT=5000 and DATABASE_URL
   npm run dev
   # Backend runs at http://localhost:5000

C. Run Frontend:
   # In the root project directory:
   python -m http.server 3000
   # Open browser at http://localhost:3000

D. Instant Backend URL Switching:
   You can point your frontend to any backend anytime using the browser console:
   localStorage.setItem('gobeyond_backend_url', 'https://frontend-project-2-way8.onrender.com');
   location.reload();
